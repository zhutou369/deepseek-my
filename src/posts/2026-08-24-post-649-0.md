Jangan risau, ini dia tiga langkah operasi yang korang boleh follow:**Langkah 1: Bangunkan Lapisan Panggilan API Korang dengan Interceptor Power!**Kebanyakan projek web moden sekarang (yang pakai JavaScript, React, Vue, Angular) memang selalunya guna library macam Axios atau `fetch` API. Apa kata korang buat satu 'wrapper' sendiri untuk semua panggilan API? Dalam wrapper inilah korang boleh sumbat semua logik interceptor tu.Contoh pseudo-kod JavaScript (jangan risau, ini basic je!):```javascript// Letak dalam fail apiService.js korangimport axios from 'axios';const deepseekApi = axios.create({  baseURL: 'https://api.deepseek.com/v1',  headers: { 'Authorization': `Bearer YOUR_API_KEY` }});deepseekApi.interceptors.response.use(  response => {    // Kalau respon OK (2xx), biarkan je dia lalu    return response;  },  error => {    // Kalau ada error, tangkap cepat-cepat kat sini!    console.error('API call failed:', error.response || error.message);    if (error.response) {      if (error.response.status === 401) {        // Handle Unauthorized: maybe redirect to login page        console.log('API Key korang mungkin dah expired atau salah. Better check balik kat DeepSeek platform.');        // Contoh: Redirect ke halaman login      } else if (error.response.status === 500) {        // Handle Server Error: boleh try again atau bagi data backup        console.log('DeepSeek server tengah meragam. Mohon cuba lagi sekejap.');      }    }    return Promise.reject(error); // Penting ni, kena pass error ke bahagian lain  });export default deepseekApi;```Nampak tak? Dengan kod ni, setiap kali korang panggil `deepseekApi.post('/chat/completions', data)`, interceptor tu akan jadi 'mata-mata' yang tengok respon dulu. Ini memang banyak bantu kita urus isu-isu macam [limit penggunaan API DeepSeek](/posts/deepseek-api-key-and-limits/) atau bila internet kat rumah buat hal. Dalam komponen UI korang, bila ada panggilan API, korang kena siap sedia dengan pelan B untuk handle kalau API tu gagal. Ini boleh jadi dengan tunjuk mesej lain, guna data yang dah ada, atau tukar terus rupa elemen tertentu.Contoh pakai React (ni pun basic je, korang boleh customize!):```jsx// Dalam komponen React korangimport React, { useState, useEffect } from 'react';import deepseekApi from './apiService'; // Ingat, import apiService yang ada interceptor tadifunction AIChatComponent() {  const [response, setResponse] = useState(null);  const [loading, setLoading] = useState(true);  const [error, setError] = useState(null);  const [fallbackMode, setFallbackMode] = useState(false);  useEffect(() => {    const fetchAIResponse = async () => {      try {        setLoading(true);        setError(null);        const res = await deepseekApi.post('/chat/completions', {          model: 'deepseek-chat',          messages: [{ role: 'user', content: 'Berikan ringkasan tentang DeepSeek API.' }],        });        setResponse(res.data.choices[0].message.content);      } catch (err) {        setError('Oops, gagal nak dapat respon AI. Jom cuba mod fallback.');        setFallbackMode(true); // Yes, aktifkan mod fallback!        // Kat sini lah kita guna data cache atau mesej yang umum        setResponse('Maaf sangat, DeepSeek API tengah busy. Sabor ye.</div>;  if (error && fallbackMode) return <div>{error}<p>{response}</p></div>; // Kita tunjuk fallback!  if (error) return <div>Alamak, ada masalah: {error}</div>;  return (    <div>      <h2>Respon DeepSeek AI Korang:</h2>      <p>{response}</p>      {fallbackMode && <p><i>(Fungsi ini guna mod fallback sebab API ada masalah)</i></p>}    </div>  );};export default AIChatComponent;```**Langkah 3: Jangan Lupa Monitor & Bagi Notifikasi!**Jangan pulak dah set semua ni, lepastu terus lupa! Apa beza interceptor dengan error handling biasa yang kita letak dalam `try-catch` tu?**Interceptor ni macam pengawal keselamatan global. Dia akan tangkap semua respon (dan request) dari satu pintu utama. Ini bermakna korang tak payah nak ulang tulis kod `try-catch` yang sama banyak kali kat setiap panggilan API. Memang power untuk urus logik error handling, logging, atau nak tukar-tukar data secara konsisten kat semua bahagian aplikasi. `try-catch` pulak, dia lebih spesifik, untuk handle error kat satu-satu panggilan API je.**2. Penting sangat ke graceful degradation ni untuk PKS yang baru nak berjinak dengan DeepSeek API?**Ya Allah, penting sangat! Untuk PKS, setiap user tu macam emas. Kalau user dapat pengalaman teruk (aplikasi crash, keluar skrin error yang hodoh), memang senang sangat la dorang nak blah. Dengan graceful degradation, korang boleh pastikan aplikasi tu sentiasa 'bernafas' dan masih bagi value, walaupun fungsi AI DeepSeek tengah 'cuti' sekejap. Ini lah cara terbaik nak jaga reputasi dan kepercayaan user korang.**3. Macam mana nak guna interceptor kalau projek JavaScript saya tak pakai Axios?**Tak guna Axios pun takpe! Korang boleh buat 'wrapper' sendiri untuk fungsi `fetch` tu. Caranya, tulis satu fungsi yang akan bungkus `fetch` asal, dan dalam fungsi tu lah korang boleh sumbat logik interceptor korang. Konsep dia sama je: tangkap respon, proses sikit kalau perlu, dan teruskan atau handle error macam biasa.**4. Ada contoh graceful degradation yang best lagi tak selain tunjuk mesej error atau guna data cache?**Ada je! Selain mesej dan cache, korang boleh consider:*   **Fungyen terhad:** Contohnya, kalau DeepSeek tu guna untuk translate, bila API down, korang boleh la sembunyikan butang translate tu, atau sediakan option translate manual yang lagi simple.*   **Fallback ke model AI kecik/lokal:** Kalau korang ada model AI yang lebih ringan sikit dan boleh jalan secara lokal (contohnya dengan Ollama, tapi ni kena ada grafik kad yang power sikit), korang boleh switch ke situ bila API DeepSeek buat hal.*   **Minta user input manual:** Kalau fungsi auto-complete AI tak jalan, minta user masukkan data tu sendiri secara manual.**5.
