## Apa Itu Ralat 401 Unauthorized?

Dari sudut teknikal, ralat HTTP 401 Unauthorized ni adalah respons dari server yang menyatakan permintaan klien (aplikasi kita) tak ada 'ID' yang sah. Maksudnya, bukan korang tak dibenarkan akses, tapi korang belum lagi 'diperkenalkan' dengan betul kepada server. Dalam konteks DeepSeek API, ini hampir selalu merujuk kepada API key korang yang bermasalah. Server DeepSeek tak dapat nak cam identiti korang guna API key yang diberikan, atau lagi teruk, tak ada API key langsung!

Selalunya, ralat ni akan datang dengan mesej tambahan macam `Invalid Authentication`, `Missing Authorization Header`, atau `Bad Credentials`. Cuba fahamkan mesej ni, sebab ia boleh bagi petunjuk awal kat mana masalah tu bersembunyi.

## Kenapa Ia Berlaku? Punca-Punca Utama

Jom kita tengok kenapa pulak ralat '401 Unauthorized' DeepSeek API ni boleh muncul. Punca-punca utamanya termasuklah:

1.  **API Key Salah atau Tak Wujud**: Ini memang punca nombor satu! Mungkin korang tersalah salin, tersalah guna API key dari persekitaran lain (contoh: development vs production), atau API key tu dah dipadam/dibatalkan. Kadang-kadang, kita cuai sikit masa salin.
2.  **Header `Authorization` Tak Betul**: Korang mungkin terlupa nak sertakan header ni, tersalah format (contoh: bukan `Bearer YOUR_API_KEY`), atau guna nama header yang salah. Detail kecil, tapi impact besar!
3.  **API Key Dah Luput atau Dibatalkan**: API key ada tempoh sah laku, sama macam lesen. Mungkin korang (atau admin akaun) dah batalkannya atas sebab keselamatan, atau dah expired.
4.  **Masalah Rangkaian atau Firewall**: Walaupun tak kerap sangat, kadang-kadang masalah pada rangkaian internet korang atau firewall boleh menyekat header `Authorization` yang penting dari sampai ke server.

## Langkah Demi Langkah: Betulkan DeepSeek API 401 Unauthorized

Jadi, jom kita bedah satu per satu langkah-langkah praktikal untuk menyelesaikan isu ni. Anggaplah kita menggunakan Python `requests` library sebagai contoh, tapi konsepnya sama je untuk bahasa pengaturcaraan lain atau `curl`.

### Langkah 1: Semak API Key Anda Macam Cari Harta Karun

Ini adalah langkah paling-paling kritikal. Korang kena pastikan API key yang digunakan tu memang betul dan aktif dari akaun DeepSeek korang. Ia macam kunci pintu utama rumah, penting sangat!

*   **Log Masuk ke DeepSeek Platform**: Pergi ke [laman DeepSeek Platform](https://platform.deepseek.com) dan log masuk ke akaun korang. Kalau rasa pening nak log masuk, boleh je jenguk [panduan penyelesaian masalah log masuk DeepSeek kami](/posts/deepseek-web-login-troubleshoot/).
*   **Navigasi ke Bahagian API Keys**: Cari bahagian 'API Keys' atau 'Credentials'. Kat sana, korang akan nampak senarai API key yang sedia ada.
*   **Buat API Key Baharu (Kalau Perlu)**: Kalau korang tak pasti mana satu key yang betul atau ada rasa ragu-ragu, saya cadangkan untuk jana API key baharu. Salin key baharu ni dan pastikan korang simpan di tempat yang sangat-sangat selamat, macam harta karun peribadi. Jangan sekali-kali letak API key korang terus dalam kod sumber yang akan di-commit ke repositori awam, itu minta bahaya namanya!

*   **Gantikan API Key dalam Kod Korang**: Guna API key yang dah korang sahkan atau key baharu yang dijana tu untuk ganti key lama dalam kod. Kalau korang guna `environment variables` (yang memang sangat-sangat disyorkan), pastikan nilai `environment variable` tu dah dikemas kini.

Contoh penggunaan `environment variable` dalam Python (cara yang lebih selamat):

```python
import os
import requests

DEEPSEEK_API_KEY = os.getenv("DEEPSEEK_API_KEY")

if not DEEPSEEK_API_KEY:
    print("Error: DEEPSEEK_API_KEY environment variable not set.")
    exit()

headers = {
    "Authorization": f"Bearer {DEEPSEEK_API_KEY}",
    "Content-Type": "application/json"
}

# ... rest of your API call
```

### Langkah 2: Sahkan Penggunaan Header HTTP yang Betul (Ejaan Penting!)

DeepSeek API, sama macam kebanyakan API moden lain, mengharapkan API key korang dihantar melalui header `Authorization` dengan skema `Bearer`. Ini adalah standard industri, so jangan pandai-pandai ubah formatnya.

*   **Format Header**: Pastikan formatnya betul-betul `"Authorization": "Bearer YOUR_API_KEY"`. Ingat, ada perkataan `Bearer` diikuti dengan satu ruang, kemudian barulah API key korang. Titik dan koma pun penting!
*   **Tiada Kesilapan Ejaan**: Semak ejaan `Authorization` dan `Bearer`. Kesilapan kecil, walaupun satu huruf, boleh menyebabkan ralat 401 ni muncul. Percayalah, dah banyak kali jadi!

Contoh yang betul:

```python
headers = {
    "Authorization": "Bearer sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx", # Ganti dengan API Key anda yang sebenar!
    "Content-Type": "application/json"
}

# Permintaan POST contoh
response = requests.post("https://api.deepseek.com/chat/completions", headers=headers, json={
    "model": "deepseek-chat",
    "messages": [
        {"role": "user", "content": "Hello, DeepSeek!"}
    ]
})

print(response.status_code)
print(response.json())
```

### Langkah 3: Pastikan Tiada Kesilapan Taip atau Ruang Berlebihan (Human Error)

Memang nampak remeh, tapi percayalah, ini antara punca paling kerap berlaku! Kadang-kadang, ralat 401 ni datang dari kesilapan manusia yang kita tak perasan pun:

*   **Ruang Berlebihan (Whitespace)**: Masa korang salin API key, pastikan tak tersalin ruang kosong tambahan kat awal atau akhir key tu. Walaupun satu ruang kecil, server akan anggap key korang tu tak sah.
*   **Kesilapan Taip**: Periksa balik API key korang untuk sebarang kesilapan taip. Satu huruf atau nombor yang salah dah cukup untuk buat pengesahan gagal. Cuba salin semula, jangan taip.
*   **Karakter Khas**: Pastikan tak ada karakter pelik-pelik yang tersalah salin kalau korang guna kaedah salin-tampal.

### Langkah 4: Semak Had Penggunaan & Status Akaun Korang

Walaupun jarang menjadi punca terus ralat 401 (biasanya korang akan dapat 429 Too Many Requests atau 403 Forbidden kalau isu ni), tapi ada kalanya masalah berkaitan akaun boleh jugak menyumbang kepada masalah pengesahan ni. Tak salah kalau kita double check, betul tak?

*   **Had Penggunaan (Rate Limits)**: Pastikan korang tak melebihi had penggunaan API DeepSeek. Kalau korang buat terlalu banyak permintaan dalam masa yang singkat, API mungkin akan mula menolak permintaan korang, kadang-kala dengan respons yang mengelirukan. Kalau nak tahu lebih lanjut pasal [pengurusan API key dan had penggunaan DeepSeek](/posts/deepseek-api-key-and-limits/), ada panduan kami yang lain yang boleh korang selongkar.
*   **Status Akaun**: Pastikan akaun DeepSeek korang dalam keadaan baik dan tak digantung atau ada masalah pembayaran. Apabila saya sendiri dulu tengah buat testing, pernah juga dapat ralat yang lebih kurang sama sebab kad kredit yang saya guna untuk pembayaran automatik dah tamat tempoh, menyebabkan akaun saya disekat sementara. ## Soalan Lazim (FAQ)

Berikut adalah beberapa soalan yang selalu ditanya pasal ralat 401 Unauthorized dan DeepSeek API. Jom kita bedah jawapannya!

**S1: Apa beza ralat 401 Unauthorized dengan 403 Forbidden?**
J: Ralat 401 Unauthorized ni maksudnya server tak dapat nak cam identiti korang (ada masalah dengan API key atau cara korang hantar key tu). Manakala, ralat 403 Forbidden pulak bermaksud server dah kenal siapa korang, tapi korang tak ada kebenaran untuk akses benda yang diminta (contoh: akaun korang tak ada akses ke model tertentu, atau peranan korang tak membenarkan tindakan tu). Macam korang ada kunci rumah, tapi tak ada kunci bilik tertentu.

**S2: Boleh saya letak API key saya terus dalam kod?**
J: Jangan sesekali! Ini memang amalan keselamatan yang sangat-sangat tak bagus dan boleh membahayakan. API key korang mungkin terdedah kalau kod korang dikongsi atau diletakkan di repositori awam. Sebaiknya, gunakan `environment variables` atau sistem pengurusan rahsia (secret management system) yang lain. Cara ni lebih pro dan selamat, lagipun korang boleh tukar API key tanpa perlu sentuh kod asal.

**S3: Saya dah semak semua langkah, tapi masih dapat 401. Apa lagi yang boleh saya buat?**
J: Ini memang situasi yang boleh buat kita garu kepala, kan? Cuba untuk membuat permintaan `curl` terus dari terminal korang untuk asingkan masalah. Kalau `curl` berfungsi, masalah mungkin terletak pada kod aplikasi korang. Tapi kalau `curl` pun tak jalan, masalah mungkin pada API key tu sendiri atau konfigurasi rangkaian korang. Korang juga boleh cuba jana API key baharu sebagai langkah terakhir sebelum terus menghubungi sokongan DeepSeek.

**S4: Adakah penting untuk pusing (rotate) API key saya secara berkala?**
J: Ya, sangat penting! Ia adalah amalan keselamatan yang sangat baik, terutamanya untuk akaun produksi atau kalau API key korang digunakan oleh beberapa aplikasi/pasukan. Dengan memusing API key, korang mengurangkan risiko sekiranya key tersebut terdedah. Banyak syarikat PKS yang smart memang ada polisi pusingan API key setiap beberapa bulan sekali.

**S5: Bagaimana jika saya tersalah dedahkan API key DeepSeek saya?**
J: Kalau korang rasa API key dah terdedah atau jatuh ke tangan yang salah, segera log masuk ke DeepSeek Platform korang dan batalkan (revoke) key yang terdedah tu. Kemudian, jana API key baharu dan kemas kini semua aplikasi yang menggunakannya. Ini adalah langkah kritikal untuk lindungi akaun dan penggunaan API korang daripada disalahgunakan. Cepat bertindak, ya!
