## Kenapa API Key Penting?

Fikirkan API key ni macam kunci rumah korang sendiri. Tanpa kunci, memang tak boleh la nak masuk atau guna apa-apa dalam rumah tu, kan? Sama macam tu, dalam dunia DeepSeek, API key ni berfungsi sebagai "pasport" untuk aplikasi Node.js korang. Ia membolehkan aplikasi korang "bersembang" dengan server DeepSeek dan guna model-model AI diorang. Setiap kali korang hantar permintaan, kunci ni akan "mengesahkan" identiti korang. Ini penting tau, sebab ia pastikan cuma korang (atau sesiapa yang korang benarkan) je boleh akses servis tu. Selain tu, DeepSeek juga guna kunci ni untuk rekod penggunaan dan bil korang. Cuba bayangkan, kalau API key korang bocor, orang lain boleh sesuka hati guna akaun korang untuk buat permintaan, dan hujung bulan nanti, bil korang boleh melambung tinggi! Aduhai, tak ke naya tu? ## Langkah 2: Pasang DeepSeek Node.js SDK

Bab nak pasang SDK DeepSeek ni, memang senang macam petik jari je. Tak payah pening kepala. Korang cuma perlu buka terminal atau Command Prompt, pergi ke folder projek Node.js korang, lepas tu taip je arahan ni:

## Langkah 3: Masukkan API Key ke dalam Kod Anda

Okay, ni la part yang paling kritikal, geng! Ada dua cara utama untuk kita masukkan API key korang ke dalam DeepSeek Node.js SDK. Satu cara tu memang paling saya suggest dan paling selamat. Cara lagi satu tu pulak, agak 'direct' sikit, tapi ada risiko tersendiri.

### Kaedah A: Guna Environment Variable (Disyorkan)

Ini memang cara paling cun dan selamat, takde tandingan! Korang akan simpan API key tu sebagai environment variable. Apa maksudnya? Maksudnya, kod korang akan baca kunci tu masa program berjalan, bukan disimpan dalam kod tu sendiri. Ini secara automatik menghalang API key korang daripada 'terkeluar' kalau-kalau korang ter-commit kod ke GitHub atau mana-mana tempat awam. Percayalah cakap saya, kaedah ni jimat banyak masa dan masalah di kemudian hari.

1.  **Cipta fail `.env`:** Dekat root folder projek korang, buat satu fail baru, nama dia `.env`. (Penting: Jangan lupa masukkan `.env` dalam fail `.gitignore` korang juga, supaya tak ter-upload ke Git secara tak sengaja!).
2.  **Masukkan API key:** Dalam fail `.env` tu, letak API key korang macam ni ha:

    ```
    DEEPSEEK_API_KEY="sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
    ```

    Gantikan `sk-xxxxxxxx...` tu dengan API key korang yang betul-betul punya.

3.  **Pasang `dotenv`:** Untuk Node.js boleh 'faham' dan baca fail `.env` ni, korang kena pasang satu pakej namanya `dotenv`:

    ```bash
npm install dotenv
    ```

4.  **Guna dalam kod:** Dalam fail JavaScript utama projek korang (selalunya `index.js` atau `app.js`), letakkan baris kod ni dekat paling atas:

    ```javascript
    require('dotenv').config();
    const DeepSeek = require('deepseek');

    const deepseek = new DeepSeek({
      apiKey: process.env.DEEPSEEK_API_KEY,
    });

    // Ha, sekarang dah boleh guna 'deepseek' objek ni untuk panggil API. Senang kan?
    // Contoh: deepseek.chat.completions.create({...});
    ```

    Serius, inilah cara paling kemas dan pro. Dari pengalaman saya sendiri, masa saya cuba guna cara ni untuk beberapa projek PKS, memang banyak gila membantu dalam menguruskan kunci untuk environment pembangunan (dev) dan production (prod) yang berbeza. Memang sangat-sangat recommended!

### Kaedah B: Terus dalam Kod (Kurang Disyorkan)

Okay, cara ni memang nampak lagi senang untuk setup awal-awal, atau kalau korang buat projek kecik-kecik yang korang yakin 100% takkan share kodnya kat mana-mana. **Tapi, saya nak tegaskan, saya memang TAK GALAKKAN SAMA SEKALI** korang guna cara ni untuk projek yang nak deploy ke production atau projek yang akan di-upload ke GitHub awam. Ini bahaya, korang! Saya ulang, bahaya! Risiko kebocoran tu tinggi sangat.

## Contoh Kod Penuh: Memanggil API DeepSeek

Okeh, sekarang dah setel bab API key, masa untuk beraksi! Jom kita tengok contoh kod penuh macam mana nak buat panggilan API yang simple tapi berkesan, nak dapatkan jawapan dari DeepSeek. Kita akan stick dengan Kaedah A (environment variable) demi keselamatan, sebab kita kan developer yang bijak.

Pastikan fail `.env` korang dah ada `DEEPSEEK_API_KEY` tu ye. Lepas tu, buat satu fail baru, nama dia `index.js`:

```javascript
require('dotenv').config(); // Ini untuk muatkan semua environment variables dari .env
const DeepSeek = require('deepseek');

const deepseek = new DeepSeek({
  apiKey: process.env.DEEPSEEK_API_KEY, // Kunci API kita ambik terus dari environment variable
});

async function main() {
  try {
    const chatCompletion = await deepseek.chat.completions.create({
      model: "deepseek-chat", // Boleh pilih model lain kalau nak, ikut suka korang
      messages: [
        { role: "user", content: "Berikan saya 3 fakta menarik tentang Malaysia" }
      ],
      temperature: 0.7,
      max_tokens: 150
    });

    console.log("Jawapan dari DeepSeek ni ha:");
    console.log(chatCompletion.choices[0].message.content);

  } catch (error) {
    console.error("Aduhai, ada error la masa nak panggil API DeepSeek:", error);
    if (error.response) {
      console.error("Status Error:", error.response.status);
      console.error("Data Error:", error.response.data);
    }
  }
}

main();
```

Untuk running kod ni, simpan sebagai `index.js` dan jalankan di terminal korang:

```bash
node index.js
```

Kalau semua berjalan lancar, korang akan nampak jawapan dari DeepSeek terpapar kat konsol. Tahniah! Korang dah berjaya 'bersembang' dengan AI DeepSeek. Kalau nak power lagi bab buat [asas prompt DeepSeek](/posts/deepseek-prompt-basics/) yang betul-betul efektif, boleh la jenguk panduan kami yang satu lagi tu.

## Tip Tambahan Untuk Keselamatan API Key

Okay, bab keselamatan API key ni, memang bukan benda boleh buat main-main, tau! Kalau bocor, menangis tak berlagu nanti. Jadi, ni ada beberapa tips ekstra yang korang boleh pakai untuk pastikan kunci korang selamat:

*   **Jangan "hardcode" langsung:** Saya dah tekankan banyak kali, tolong sangat-sangat elakkan letak API key korang direct dalam kod. Lagi-lagi kalau projek tu nak publish ke public atau untuk production. Memang cari nahas namanya!
*   **Guna Pengurus Rahsia (Secret Manager):** Untuk aplikasi yang lebih besar atau kalau korang deploy kat cloud, saya highly suggest korang fikirkan untuk guna servis pengurusan rahsia macam AWS Secrets Manager, Azure Key Vault, atau HashiCorp Vault. Benda ni bagi satu lagi lapisan perlindungan yang mantap.
*   **Hadkan Siapa Boleh Akses:** Kalau kerja dalam team, bagi akses API key tu kat orang yang betul-betul perlukan je. Ikut prinsip "least privilege" ni, memang terbaik.
*   **Sentiasa Check Log:** Rajin-rajinkan la pantau log penggunaan API korang. Kalau ada aktiviti pelik-pelik, korang boleh kesan cepat-cepat. Tips ni ada kaitan juga dengan [panduan API retry kami](/posts/deepseek-api-retry-guide/) kalau-kalau ada masalah sambungan yang asyik ulang-ulang.
*   **Tukar Key Selalu:** Amalkan tukar API key korang secara berkala, contohnya setiap beberapa bulan. Ini memang amalan keselamatan yang sangat bagus. Kalau korang ada main-main dengan model AI tempatan macam [DeepSeek dan Ollama](/posts/deepseek-ollama-local-setup/), pastikan kunci untuk model cloud korang tu diuruskan asing-asing dan jaga betul-betul selamat.

## Soalan Lazim (FAQ)

**S1: Apa jadi kalau saya langsung tak letak API key?**

**J:** Kalau korang tak masukkan API key langsung, atau key yang korang letak tu tak sah, DeepSeek SDK akan bagi respon error "Authentication Error" atau "Invalid API Key". Kiranya, memang tak dapat la korang nak buat apa-apa panggilan API ke servis DeepSeek tu. Jadi, make sure ada key yang valid, ya.

**S2: Boleh ke guna lebih dari satu API key dalam satu projek?**

**J:** Boleh je, takde masalah! Korang boleh cipta beberapa `DeepSeek` client instance. Setiap instance tu boleh guna API key yang berbeza, contohnya kalau korang ada keperluan nak uruskan akses berlainan untuk modul-modul lain, atau untuk asingkan bil.

**S3: Aduh! API key saya 'terbocor' di GitHub. Apa patut saya buat?**

**J:** Cepat-cepat login ke akaun DeepSeek korang di [platform.deepseek.com](https://platform.deepseek.com/) dan terus "revoke" (batalkan) API key yang dah terdedah tu. Lepas tu, generate key baru dan gantikan dalam projek korang. Jangan lupa pulak, kalau boleh, bersihkan history commit GitHub korang tu. DeepSeek pun ada panduan pasal [penyelesaian masalah log masuk web](/posts/deepseek-web-login-troubleshoot/) kalau korang ada isu dengan akaun.

**S4: Pakej `dotenv` ni selamat ke kalau guna untuk production?**

**J:** `dotenv` ni memang sangat bagus untuk kita handle environment variables masa proses pembangunan (development). Tapi, untuk production, kebanyakan platform cloud (macam Heroku, Vercel, AWS Elastic Beanstalk, dan lain-lain) ada cara tersendiri yang lebih proper untuk uruskan environment variables. Korang boleh set environment variables ni direct je kat platform hosting tu, dan kod Node.js korang (yang guna `process.env.DEEPSEEK_API_KEY`) akan baca terus secara automatik tanpa perlu fail `.env` atau pakej `dotenv` tu sendiri.

**S5: Selain API key, ada parameter penting lain tak masa nak initialize `DeepSeek` client?**

**J:** Ya, memang ada! Selain `apiKey` yang wajib tu, korang boleh juga set `baseURL` kalau-kalau korang guna custom endpoint atau proxy. Ada jugak parameter lain untuk konfigurasi `fetch` macam `timeout`. Tapi, saya tegaskan sekali lagi, `apiKey` tu memang paling asas dan wajib ada. Tanpanya, memang tak jalanlah cerita.
