## Apa Sebenarnya Ralat 400 (Bad Request) Tu?
Ralat 400, atau nama penuhnya 'Bad Request', ni ibarat server DeepSeek (atau mana-mana server lain) tengah bagi tahu kita, 'Maaf, saya tak faham apa yang awak nak ni.' Bayangkan macam anda pergi kedai kopi, tapi order menu yang tak wujud. Jadi, barista tu tak fahamlah, kan? Samalah juga, server tak dapat proses permintaan yang aplikasi, browser, atau kod API anda hantar sebab ada 'sesuatu' yang tak kena dengan formatnya. Paling penting, ralat ni biasanya berpunca dari sebelah kita (client), bukan server tu yang rosak. Jadi, berita baiknya, kita ada kuasa penuh untuk betulkan!

## Kenapa Ralat 400 Boleh Berlaku Dengan DeepSeek (dan aplikasi PKS lain)?
Jadi, kenapa pulak Ralat 400 ni boleh muncul masa kita guna DeepSeek atau aplikasi PKS lain? Meh sini saya cerita beberapa punca biasa yang saya selalu jumpa:

1.  **Data Permintaan Tak Betul atau Tak Lengkap (Payload):** Apabila anda menghantar data JSON ke DeepSeek API, contohnya, jika ada tanda koma yang salah, kurungan yang tak tutup, atau missing field yang wajib ada. Ini adalah punca paling kerap saya jumpa.
2.  **Header HTTP Berterabur atau Tak Ada:** Mungkin anda lupa sertakan `Content-Type: application/json` untuk permintaan JSON, atau `Authorization` header yang sepatutnya ada [DeepSeek API key anda](/posts/deepseek-api-key-and-limits/). Server tak tahu bagaimana nak proses permintaan tanpa maklumat penting ini.
3.  **URL atau Alamat Endpoint Tersalah Eja:** Ada typo pada alamat URL DeepSeek API yang anda cuba capai. Setiap API ada `endpoint` spesifik, dan kalau salah, server tak tahu nak hantar permintaan anda ke mana.
4.  **Parameter Query (macam ?model=deepseek-chat) Tak Sah:** Jika anda ada parameter tambahan pada URL, tapi formatnya salah atau parameter itu tak diiktiraf oleh API.
5.  **Permintaan Terlalu Besar:** Walaupun jarang, ada had saiz untuk setiap permintaan. Jika anda hantar prompt yang terlalu panjang atau fail yang besar, ia mungkin menyebabkan Ralat 400.

## Panduan Langkah Demi Langkah Selesaikan Ralat 400

Relax, jangan panik! Mari kita ikut langkah-langkah ni satu persatu untuk trace dan selesaikan Ralat 400 yang mengganggu tu.

### Langkah 1: Periksa Data Permintaan Anda (Payload JSON/XML)
Okay, ini memang langkah paling *basic* tapi paling kritikal. Majoriti Ralat 400 ni datangnya dari data yang kita hantar tu sendiri. Pastikan formatnya betul-betul ikut spec!

*   **Untuk API DeepSeek:** Sila *double-check* balik payload JSON anda. Betul ke JSON tu sah? Guna je *online JSON validator* kalau tak yakin. Pastikan semua *field* yang wajib ada (macam `model`, `messages`, `max_tokens`) lengkap dan formatnya *ngam-ngam*. Ingat, satu koma salah tempat, satu kurungan tak tutup, boleh jadi punca masalah besar. Contohnya, `"messages": [{ "role": "user", "content": "Hello" }]` tu kena sebiji macam tu, tak boleh silap.
*   **Untuk borang web:** Kalau anda tengah isi borang online tiba-tiba keluar Ralat 400, mungkin ada *field* yang tertinggal kosong, atau anda masukkan data yang salah jenis (contohnya, letak teks dekat *field* nombor).

**Tips Pro (dengan Developer Tools):** Buka tab 'Network' dalam *developer tools* browser anda (tekan `F12`). Cari *request* yang bagi Ralat 400 tu. Klik kat *request* tersebut, lepas tu tengok tab 'Payload' atau 'Request Body'. Kat situ, anda boleh nampak data mentah yang dihantar. Sahkan balik ia betul.

### Langkah 2: Semak Header HTTP (API Key, Content-Type)
Header HTTP ni macam label pada parcel kita. Dia bagitahu server, 'Eh, aku hantar barang jenis ni, dan ini identiti aku.'

*   **`Content-Type`:** Kalau anda hantar JSON, pastikan ada header `Content-Type: application/json`. Kalau hantar XML, guna `application/xml`.
*   **`Authorization`:** Untuk kebanyakan API (termasuk DeepSeek), anda perlu sertakan API key untuk nak bagi server cam kita. Pastikan ia dalam format `Authorization: Bearer YOUR_API_KEY`. API key yang salah atau tidak wujud akan menyebabkan server tidak menerima permintaan anda. Cuba baca [panduan penggunaan DeepSeek API key](/posts/deepseek-api-key-and-limits/) untuk maklumat lanjut.

**Tips Pro (dengan Developer Tools):** Dalam tab 'Network' yang sama, klik pada permintaan Ralat 400, kemudian pergi ke tab 'Headers'. Tinjau bahagian 'Request Headers'. Pastikan `Content-Type` dan `Authorization` (jika perlu) ada dan nilainya betul.

### Langkah 3: Sahkan URL atau Endpoint
URL tersalah eja, nampak macam remeh, tapi inilah punca Ralat 400 yang selalu buat kita garu kepala. Setiap fungsi API DeepSeek tu ada 'alamat' (`endpoint`) dia yang spesifik.

*   *Double-check* URL yang anda gunakan. Bandingkan dengan dokumentasi rasmi DeepSeek. Adakah anda guna `https://api.deepseek.com/chat/completions` atau ada typo seperti `https://api.deepseek.com/chat/completion` (missing 's')?
*   Untuk sistem tempatan atau pelayan mandiri, pastikan alamat IP atau nama domain yang anda gunakan adalah betul dan boleh diakses.

**Tips Pro (dengan Developer Tools):** Dalam tab 'Network' browser anda, lihat bahagian 'Request URL'. Pastikan URL yang tertera sama sebiji dengan apa yang sepatutnya.

### Langkah 4: Semak Had Saiz Permintaan
Kadang-kadang, walaupun tak selalu sangat, permintaan anda terlalu besar untuk diproses server. Ini boleh jadi untuk `prompt` yang sangat panjang atau data fail yang dihantar melalui API.

*   Cuba hantar permintaan yang lebih kecil atau ringkas. Jika ia berjaya, ini mungkin petunjuk saiz data memang masalahnya. Saya pernah berdepan dengan isu ini semasa membantu sebuah PKS memproses satu batch data yang sangat besar melalui API pihak ketiga. Kami terpaksa pecahkan data kepada segmen lebih kecil.

### Langkah 5: Cuba Ulang Dengan Parameter Ringkas
Kalau Ralat 400 masih tak nak pergi, strategi terbaik selalunya adalah mulakan dengan permintaan yang paling asas atau paling ringkas. Untuk API DeepSeek, ini bermaksud `prompt` yang ringkas, tanpa banyak parameter tambahan (seperti `temperature`, `top_p`, `stream`).

*   Jika permintaan ringkas berjaya, ia menunjukkan masalah ada pada salah satu parameter tambahan yang anda gunakan. Dari situ, anda boleh *add-on* parameter satu per satu, sampai lah anda jumpa 'siapa' sebenarnya punca Ralat 400 tu.

### Langkah 6: Log Debug & Mesej Ralat
Yang ini, kita panggil 'golden hint' atau 'petunjuk emas'! Apabila server mengembalikan Ralat 400, ia selalunya akan sertakan mesej ralat tambahan yang lebih spesifik dalam 'body' responsnya. Mesej ini boleh jadi sangat membantu.

*   **Untuk API:** Dalam kod anda, pastikan anda log respons penuh dari API, bukan hanya kod status. Mesej ralat dari [platform DeepSeek](https://platform.deepseek.com/) selalunya sangat deskriptif, contohnya, "Invalid JSON payload. Expected string at 'messages[0].content' ". Ini akan terus tunjukkan di mana silapnya.
*   **Untuk aplikasi web:** Kadang-kadang, mesej ralat dipaparkan di skrin atau dalam *console log* browser (tab 'Console' dalam `F12`).

**Tips Pro (dengan Developer Tools):** Dalam tab 'Network', setelah klik pada permintaan Ralat 400, lihat tab 'Response'. Di situ akan tertera mesej ralat dari server. Salin dan analisis mesej tersebut. Barulah kita tahu, apa benda yang 'bad' sangat dalam *request* kita tu. Anda juga boleh cuba [bagaimana untuk retry API call anda](/posts/deepseek-api-retry-guide/) jika ia masalah sementara.

### Langkah 7: Clear Cache & Cookies (untuk isu web interface)
Jika Ralat 400 berlaku apabila anda cuba berinteraksi dengan antaramuka web DeepSeek (seperti chat.deepseek.com atau platform.deepseek.com) dan bukannya API, ini mungkin petanda cache atau cookies browser anda dah 'meragam'. Data lama yang disimpan boleh mengganggu permintaan baru.

*   Cuba bersihkan cache dan cookies browser anda, kemudian cuba lagi. Kadang-kadang, cara paling *simple* ni lah yang selesaikan masalah paling misteri! Baca juga [panduan atasi isu log masuk](/posts/deepseek-web-login-troubleshoot/) jika ia melibatkan akses ke portal web DeepSeek.

## Soalan Lazim (FAQ) Tentang Ralat 400

**S1: Adakah Ralat 400 ni masalah server saya ke?**
J1: Tidak. Ralat 400 hampir 99% menunjukkan masalah datang dari *request* yang kita hantar sendiri (dari aplikasi atau browser kita). Server cuma nak bagitahu dia tak faham arahan kita, bukan server tu yang rosak. Jangan salahkan server dulu, ya!

**S2: Boleh ke saya guna AI untuk bantu debug Ralat 400?**
J2: Ya, sudah tentu! Ini adalah salah satu *superpower* AI yang boleh kita guna! Anda boleh salin mesej ralat yang anda dapat, atau bahkan kod permintaan anda (pastikan tiada maklumat sensitif!), dan minta model AI seperti DeepSeek Chat untuk menganalisis dan mencadangkan penyelesaian. Dia boleh jadi 'pair programmer' kita yang *super* efektif.

**S3: Kalau DeepSeek API beri Ralat 400, apa patut saya buat dulu?**
J3: Pertama sekali, semak payload JSON anda. Ini punca nombor satu! Gunakan *JSON validator* dan pastikan semua *field* yang wajib ada sudah disertakan dan formatnya betul. Kalau itu dah confirm okay, baru kita jenguk header dan URL.

**S4: Apa kaitan "Prompt Engineering" dengan Ralat 400?**
J4: Secara *direct*nya, Ralat 400 ni bukan isu *prompt engineering*. *Prompt engineering* lebih kepada cara anda membina arahan supaya AI faham dan beri respons yang bagus. Namun, jika *prompt* anda terlalu panjang sehingga melebihi had saiz permintaan API, atau anda cuba masukkan jenis data yang salah dalam `content` *field* bagi sebuah `message`, ia boleh menyumbang kepada Ralat 400. Memahami [cara terbaik membina prompt](/posts/deepseek-prompt-basics/) boleh bantu kita elak isu-isu macam ni sedikit sebanyak.

## Tip Tambahan Untuk PKS Malaysia

*   **Guna *Tool Debugging*:** Browser web moden ada *developer tools* yang sangat-sangat hebat. Belajar cara menggunakan tab 'Network' dan 'Console' memang *power* untuk kita *debug* masalah web dan API.
